# مَدار | MADAR

**إدارة الأفراد، وتنمية الأعمال.**

نظام عربي مستقل لتشغيل خدمات الموارد البشرية لعدة شركات. هذا إصدار أساسي قابل للتشغيل **0.1.0**، وليس منتجًا مكتمل الاعتماد أو بديلًا جاهزًا لجميع خدمات الشركات المذكورة في فكرة المشروع. لا يوجد ارتباط برمجي أو حسابات أو بيانات من أي مشروع آخر.

## بدء التشغيل

يتطلب Python 3.12 أو أحدث. لا يحتاج تثبيت مكتبات، ولا يوجد حساب افتراضي أو كلمة مرور داخل الكود.

```bash
python server.py init --email admin@your-company.com --name "مدير مدار"
python server.py
```

أدخل كلمة مرور من 12 حرفًا على الأقل في نافذة الأوامر، ثم افتح **http://127.0.0.1:8000**. المالك ينشئ المستخدمين من «المستخدمون والصلاحيات». استخدم بياناتك الحقيقية بدل البريد التوضيحي أعلاه.

على Windows يمكن استبدال `python` بـ `py`، وعلى بعض أجهزة macOS/Linux استخدم `python3`.

## تجربة ببيانات وهمية منفصلة

Linux / macOS:

```bash
export MADAR_DATA_DIR="$PWD/.demo-data"
python server.py demo
python server.py
```

PowerShell:

```powershell
$env:MADAR_DATA_DIR = "$PWD/.demo-data"
python server.py demo
python server.py
```

أمر `demo` يطبع بريدًا وكلمة مرور عشوائية جديدة في جهازك ويُرفض إذا كانت القاعدة تحتوي مستخدمين. البيانات الوهمية ليست بيانات موظفين حقيقية. لا تنشر قاعدة التجربة على الإنترنت. اخرج من المتغير أو استخدم مسارًا جديدًا لبدء قاعدة فعلية نظيفة.

## ما يعمل في هذا الإصدار

| القسم | العمليات الفعلية |
|---|---|
| العملاء | إضافة وتعديل شركة، مسؤول التواصل، القطاع، الخدمة المتعاقد عليها، إيقاف إنشاء سجلات جديدة للشركة |
| الموظفون | ملفات موظفين، أقسام، مسميات، تاريخ بدء، أساسي وبدلات وخصومات، رصيد إجازات، حالة الموظف |
| التوظيف | وظائف، شواغر، مرشحون مرتبطون بالوظيفة والشركة، تغيير مرحلة الترشيح يدويًا |
| الإجازات والطلبات | إنشاء، موافقة أو رفض مرة واحدة، منع تداخل الإجازات المعتمدة، خصم الرصيد داخل المعاملة |
| الحضور | حضور وانصراف بوقت الخادم، سجل واحد يوميًا، منع تزوير وقت الحضور عبر حقول الطلب |
| الرواتب | مسير شهري واحد لكل شركة، مبالغ بالهللة، لقطة ثابتة، اعتماد من مستخدم آخر، كشف الموظف المعتمد فقط |
| العقود | سجل عقد وتواريخ وحالة وملاحظات؛ المستند يرفع من قسم المستندات |
| المستندات | رفع وتنزيل PDF/PNG/JPG حتى 5 MB، ارتباط بالموظف، تحقق من النوع، تنزيل محمي بالصلاحية |
| خدمات العملاء | تذاكر، أولوية، تحديث حالة الخدمة |
| الفواتير | سجل داخلي، مبلغ وضريبة يحددهما المستخدم، تاريخ استحقاق، حالة؛ إجمالي حسابي في التفاصيل |
| التقارير | إحصاءات من البيانات الفعلية، تصفية بالشركة، CSV، طباعة، تصدير JSON للمالك |
| المتابعة | تنبيهات انتهاء العقود والمستندات خلال 30 يومًا أو المتأخرة |
| الحسابات | مالك وموارد بشرية وعميل وموظف، إنشاء حسابات وتعطيلها وتعيين كلمة مرور وإنهاء جلساتها |
| الحماية | جلسات بالخادم، scrypt لكلمات المرور، CSRF، فحص Origin، قفل محاولات الدخول، سجل عمليات، منع التحديث القديم |

واجهة عربية RTL ومتجاوبة، بحث في القسم، ترقيم صفحات، رسائل خطأ وحالات فارغة. الحفظ في SQLite وملفات خاصة بالخادم، وليس localStorage.

## رحلة تشغيل مقترحة

1. أنشئ حساب المالك بالطريقة أعلاه.
2. أضف شركة العميل من «العملاء والشركات».
3. أضف ملفات الموظفين والرواتب والأرصدة المعتمدة لدى العميل.
4. أنشئ حساب مسؤول العميل وحدد شركته، ثم حساب كل موظف وحدد ملفه.
5. أضف الوظائف والمرشحين والعقود ومستندات الموظفين.
6. اختبر تقديم طلب إجازة بحساب الموظف، ثم الموافقة بحساب مسؤول العميل.
7. أنشئ مستخدم HR مستقلًا ليعد مسير الرواتب. يعتمد المسير مالك أو مسؤول عميل آخر، ولا يستطيع معدّه اعتماده.
8. راجع التقارير وسجل التدقيق، وخذ نسخة احتياطية دورية.

## قواعد تحتاج معرفتها

- موظف العميل لا يرى شركات أخرى، والموظف الفردي يرى بياناته وطلباته ومستنداته ومسيراته المعتمدة فقط. فريق المدار (المالك/HR) يرى شركات التشغيل كلها بحسب دوره. انظر [مصفوفة الصلاحيات](docs/SECURITY.md).
- الإجازة **أيام تقويمية شاملة اليوم الأول والأخير**. لا يوجد محرك عطل أو عطلات رسمية أو سياسة تراكم تلقائي بعد.
- صافي الراتب = الأساسي + البدلات − الخصومات المسجلة. لا يوجد احتساب تلقائي للتأمينات أو الاستحقاق الجزئي أو الإضافي أو نهاية الخدمة. الموافقة الداخلية لا تحول أموالًا.
- لا يمكن تعديل طلب بعد إرساله؛ القرار بالموافقة أو الرفض، والطلب الجديد يعالج أي تغيير مطلوب. لا توجد إعادة إلغاء لإجازة معتمدة في هذا الإصدار.
- العقود بيانات داخلية وليست توقيعًا إلكترونيًا. الفواتير سجلات تشغيل وليست فوترة ضريبية معتمدة.
- الحضور يثبت تسجيل حساب في وقت معين، دون التحقق من موقع الموظف أو جهازه أو بصمته.
- الحساب المعطل لا يعاد تفعيله من الواجهة في هذا الإصدار. ملفات الموظفين والشركات يمكن إيقافها، ولا توجد واجهة حذف نهائي.
- الخطة المسجلة للعميل وصف للخدمة، ولا تنفذ اشتراكًا ماليًا أو تحصيلًا.

## الاختبارات

```bash
python -m unittest discover -s tests -v
python -m py_compile server.py backup.py
node --check web/app.js
```

اختبارات HTTP تستخدم قاعدة مؤقتة وتشمل عزل الشركات، صلاحيات الموظف، منع تعديل الرواتب، CSRF، تداخل/رصيد الإجازات، التعارض المتزامن، لقطة المسير ومنع تكراره والفصل بين الإعداد والاعتماد، الحضور، نوع الملفات والتنزيل المحمي، إلغاء الجلسات وقفل الدخول. ملف GitHub Actions مرفق؛ لا يعني إرفاقه أنه اشتغل في GitHub قبل رفع المشروع.

## الاستضافة والحسابات

لم تُنشأ حسابات استضافة أو قاعدة بيانات خارجية، ولم يتم نشر موقع عام. يحتاج مشروع مدار حساب استضافة مستقلًا ومساحة قرص دائمة، ثم HTTPS وتكوين `MADAR_SECURE_COOKIE=1`. **لا تستخدم استضافة ملفات ساكنة أو Vercel مباشرة لتشغيل هذا الإصدار**؛ الخادم يعتمد SQLite وقرصًا دائمًا.

الخادم القياسي هنا مخصص للتطوير والتشغيل المحدود. قبل خدمة بيانات موظفين حقيقية على الإنترنت يلزم إكمال متطلبات التشغيل والأمان الموضحة في [OPERATIONS](docs/OPERATIONS.md) و[SECURITY](docs/SECURITY.md)، واختبار حمل ومراجعة أمنية مستقلة. لا توجد مطالبة بشهادة ISO أو SOC أو مطابقة قانونية شاملة.

يستهدف هذا الكود مستودع **madar8/Madar** فقط. عند الرفع لا تضم ملفات `.env` أو البيانات أو النسخ الاحتياطية. تعليمات الرفع في وثيقة التشغيل.
