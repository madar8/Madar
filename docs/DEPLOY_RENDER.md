# نشر مدار على Render

حالة الإعداد: جاهز في المصدر، لم ينشأ حساب Render أو خدمة فعلية ضمن هذه التعديلات. لا يوجد رابط حي مؤكد بعد. هذا نشر أولي يحتاج اختبار قبول ومراجعة أمان قبل إدخال بيانات موظفين حقيقية.

## الموارد المحددة

| المورد | الإعداد |
|---|---|
| المصدر | https://github.com/madar8/Madar — main |
| Python | 3.12.14 |
| الخادم | Gunicorn 26.2.0، عامل واحد وأربع خيوط |
| الخدمة | خطة 0.5c-512mb، نسخة واحدة |
| المنطقة | Frankfurt — راجع ملاءمتها لاحتياجات إقامة بياناتك قبل النشر |
| التخزين | قرص دائم 1 GB على /var/data/madar |
| الصحة | GET /api/health |
| قاعدة البيانات | SQLite في القرص الدائم، والمستندات في مجلد files ضمنه |
| ملفات Cookie | Secure + HttpOnly + SameSite=Strict |
| التأسيس | رمز عشوائي يولده المزود، يستخدم مرة واحدة لإنشاء المالك |
| التكلفة المرجعية | خدمة 7 دولار + قرص 0.25 دولار شهريًا، قبل الضرائب والزيادات |

المصادر المرجعية: https://render.com/pricing وhttps://render.com/docs/disks وhttps://render.com/docs/blueprint-spec . السعر الملزم هو المعروض في حساب المزود قبل الموافقة. إعداد ملف النشر لا يشتري خدمة ولا يفعل اشتراكًا.

## خطوات صاحب الحساب

1. أنشئ حساب Render منفصلًا لمدار، وراجع شروط المزود بنفسك. لا تستخدم حساب استضافة أي مشروع سابق.
2. امنح تكامل Render وصولًا لمستودع madar8/Madar فقط عند طلبه. يمكنه استيراد المستودع العام؛ التفويض يتيح متابعة النشر حسب إعداداته.
3. افتح https://render.com/deploy?repo=https://github.com/madar8/Madar أو أنشئ Blueprint من المستودع.
4. راجع المنطقة والخدمة والقرص والتكلفة. لا تختَر خطة مجانية مع هذا الإصدار لأن بيانات الملفات المحلية ستفقد دون قرص دائم.
5. بعد قبولك تكلفة الخطة، أكمل إنشاء الخدمة. انتظر اكتمال البناء والنشر وفحص الصحة، واحتفظ بعنوان الخدمة الذي يعيده Render، ولا تفترض عنوانًا من اسم المشروع.
6. افتح رابط مدار. إن كانت القاعدة فارغة ستظهر شاشة تأسيس المالك.
7. من Environment في Render انسخ قيمة MADAR_SETUP_TOKEN. أدخلها في صفحة مدار نفسها مع اسمك وبريدك وكلمة مرور من 12 حرفًا على الأقل. لا ترسل الرمز أو كلمة المرور في المحادثة.
8. سجل الدخول. تأكد من قدرتك على إضافة شركة وموظف، ثم إنشاء مستخدم للعميل وتجربة نطاقه. احذف MADAR_SETUP_TOKEN من إعدادات الخدمة بعد نجاح التأسيس وأعد النشر.

## طريقة التشغيل

`buildCommand` يثبت requirements.txt. لا ينشئ قاعدة البيانات أثناء البناء؛ قرص Render لا يكون متاحًا في مرحلة build أو pre-deploy. Gunicorn يشغل ترحيلات إنشاء المخطط في post_worker_init عند التشغيل بعد توفر القرص. الترحيلات الحالية schema-only ولا تنشئ بيانات تجريبية أو مستخدمًا أو كلمة مرور.

التهيئة عبر الويب مقفلة بعد أول مستخدم. /api/health لا يكشف أسماء مستخدمين أو رموزًا أو مسارات تخزين؛ يعرض حالة الخدمة وإصدارها والحاجة للتأسيس فقط.

عند النشر دون Render يمكن استخدام نفس WSGI بعد تعيين MADAR_DATA_DIR وMADAR_SECURE_COOKIE=1 خلف HTTPS. خادم التطوير المحلي يظل متاحًا بـ python server.py. يرفض hook الخاص بـ Gunicorn بدء التشغيل على Render إذا كانت Cookie الآمنة غير مفعلة.

## حدود معروفة

- قرص دائم واحد يعني نسخة واحدة؛ لا توسع أفقيًا قبل نقل البيانات لقاعدة ومخزن ملفات مناسبين.
- Render يوقف النسخة القديمة أثناء نشر خدمة ذات قرص دائم، لذلك يوجد انقطاع قصير محتمل.
- إعداد Gunicorn يحسن طبقة تقديم HTTP، لكنه ليس دليلًا على اجتياز اختبار اختراق أو حمل أو مطابقة قانونية.
- لا توجد نسخ احتياطية خارجية مجدولة في هذا التعديل. استخدم آلية النسخ الموثقة واختبر الاستعادة، وراجع أيضًا snapshots لدى المزود.
- حفظ البيانات بعد إعادة التشغيل يجب اختباره في الخدمة الفعلية، لا يكفي نجاح الاختبارات المحلية.
- ما زالت الخدمات الحكومية والدفع والتوقيع والبنوك والبريد غير موصولة.
