# التشغيل والنشر والصيانة

## بيئات مستقلة

استخدم حسابات مدار فقط. المستودع المقصود `https://github.com/madar8/Madar`. لا تُشارك قواعد البيانات أو المتغيرات أو مزودي البريد أو حسابات الاستضافة مع مشاريع أخرى. لا يوجد في هذا المصدر اتصال بأي مشروع سابق.

تشغيل التطوير: Python 3.12+، بلا pip. اختيار `MADAR_DATA_DIR` يحدد قاعدة البيانات وملفات المستندات. ملف `.env.example` للتوثيق؛ الخادم لا يقرأ `.env` تلقائيًا.

## رفع المصدر لأول مرة

بعد فك الأرشيف، ومن داخله، مع تسجيل GitHub بحساب madar8 وصلاحية الكتابة:

```bash
git init -b main
git add .
git commit -m "Build independent Madar HR operations foundation"
git remote add origin https://github.com/madar8/Madar.git
git push -u origin main
```

لا ترسل كلمات مرور أو رموز وصول للمحادثة. استخدم مدير اعتماد GitHub الرسمي في جهازك. إذا أصبح المستودع يحتوي commits، اسحبه أولًا وراجع الفروق بدل force push. إذا رفض تطبيق GitHub المتصل الكتابة برسالة `Resource not accessible by integration` فقراءة المستودع لا تثبت صلاحية كتابة التكامل؛ يلزم إصلاح تثبيت/تفويض تطبيق ChatGPT/Codex للمستودع. لا تستخدم حساب مشروع قديم كحل بديل.

## تشغيل محدود خلف HTTPS

الخادم `http.server` القياسي مناسب للتطوير والتحقق المحدود، وليس بوابة SaaS عامة محصنة. قبل الإنتاج أعد تقييم طبقة التشغيل، واستخدم وكيل TLS وحدود طلبات ووقت اتصال ومراقبة ونسخ احتياطي وضوابط وصول. شغله كمستخدم غير root وعلى قرص دائم، واجعل الخادم الداخلي غير مكشوف للعامة.

```bash
export MADAR_DATA_DIR=/srv/madar/data
export MADAR_SECURE_COOKIE=1
python server.py init --email admin@YOUR-DOMAIN --name "مدير مدار"
python server.py serve --host 127.0.0.1 --port 8000
```

الوكيل يمرر Host كما يراه المتصفح حتى ينجح فحص Origin، ويحجب عناوين backend المباشرة. يستخدم فحص الصحة GET `/api/health` دون عرض بيانات داخلية. لا تفعّل Secure Cookie على HTTP محلي لأنه يمنع إرسال الجلسة.

صورة Docker مرفقة للتعبئة فقط؛ لم يُنفذ بناء الصورة ضمن التحقق الحالي. عند استخدامها، اربط volume دائمًا بـ `/data`، ومرر المتغيرات، وأنشئ المالك مرة واحدة تفاعليًا داخل الصورة عبر `python server.py init`. لا تدفع الصورة وفيها بيانات أو أسرار.

## النسخ والاستعادة

أوقف الخادم أثناء النسخ لضمان تزامن المستندات مع قاعدة البيانات. الأداة تستخدم SQLite backup ثم تختبر سلامة القاعدة، وتحفظ المستندات في ZIP بصلاحية 0600. الأرشيف **غير مشفر**؛ خزنه في نظام نسخ احتياطي مشفر ومقيد منفصل عن الخادم.

```bash
python backup.py --data /srv/madar/data --output /secure-backups/madar-2026-11-07.zip
```

للاستعادة: أوقف الخادم، احتفظ بالبيانات الحالية، افحص أن الأرشيف من نسختك الموثوقة، فك `madar.db` ومجلد `files` إلى مجلد بيانات جديد، طبق مالك وصلاحيات الخدمة، ثم افحص قاعدة SQLite بـ `PRAGMA integrity_check` وشغّل الخدمة بمتغير المجلد الجديد. لا تستعد فوق مجلد يعمل. اختبر تسجيل الدخول، ملف عميل، مستندًا ومسيرًا بعد الاستعادة.

تصدير JSON في الواجهة ليس بديلًا لنسخة كاملة، ولا توجد استعادة JSON من الواجهة في هذا الإصدار.

## استعادة حساب المالك من مسؤول الخادم

لا توجد استعادة بالبريد دون ربط مزود. مسؤول الخادم المخول يستطيع تنفيذ المقتطف التالي من مجلد المصدر، بعد ضبط `MADAR_DATA_DIR` نفسه. لا يطبع كلمة المرور ولا يسجلها داخل المصدر:

```python
import getpass
import server
email = input('Owner email: ').strip().lower()
with server.connect() as c:
    user = c.execute("SELECT id FROM users WHERE email=? AND role='owner'", (email,)).fetchone()
    if not user:
        raise ValueError('Owner not found')
    digest = server.hash_password(getpass.getpass('New password (12+): '))
    c.execute('UPDATE users SET password=?, active=1 WHERE id=?', (digest, user['id']))
    c.execute('DELETE FROM sessions WHERE user_id=?', (user['id'],))
```

## المراقبة والاحتفاظ

سجل العمليات داخل المنصة يحتفظ بآخر 500 نتيجة في العرض، دون حذف الأقدم من القاعدة. لا توجد سياسة حذف تلقائي. الخادم يطبع نوع خطأ داخلي فقط دون تفاصيل الطلب. قبل التشغيل التجاري عيّن سياسة احتفاظ وتخزين ومراجعة أمنية ومراقبة وقيود حجم قاعدة وملفات، واختبر تزامن الاستخدام الفعلي.
