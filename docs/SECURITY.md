## تدابير مطبقة

- استعلامات SQL ذات معاملات، معرفات عشوائية، ترشيح الحقول، رفض أنواع بيانات غير مناسبة.
- scrypt مع ملح عشوائي لكل كلمة مرور؛ لا كلمات مرور ثابتة أو مفاتيح داخل المصدر.
- معرّف جلسة عشوائي يخزن ملخصه فقط في قاعدة البيانات، 8 ساعات، Cookie: HttpOnly + SameSite=Strict، وSecure حسب الإعداد.
- CSRF لكل عملية موثقة تغير البيانات وفحص Origin حين يرسله المتصفح.
- قفل البريد بعد 10 محاولات فاشلة لمدة 15 دقيقة. لا يثق في عناوين IP المرسلة عبر وكيل.
- الجلسات تلغى عند تغيير كلمة المرور أو إعادة تعيينها أو تعطيل حساب أو تسجيل الخروج.
- عمليات الموافقة في معاملات SQLite مع قفل كتابة لمنع الخصم مرتين، ورقم نسخة لمنع ضياع التحديث.
- ملفات في مجلد غير منشور، أسماء عشوائية، تحقق بادئة النوع، حد حجم، Content-Disposition attachment وتنزيل بعد فحص الشركة والموظف.
- لا يسجل الخادم طلبات HTTP أو حمولات البيانات أو ملفات المصادقة في stdout. سجل التدقيق يسجل الفاعل والعملية والوقت ومعرف السجل فقط.
- CSP بمصادر محلية، منع تضمين الإطار، منع تخمين المحتوى، وترميز قيم المستخدم في HTML وCSV للحماية من حقن الصيغ.

## المتبقي قبل إطلاق خدمة تجارية عامة

لا يدعي هذا الإصدار اجتياز OWASP ASVS أو ISO 27001 أو SOC 2 أو أي معيار آخر. هذه أهداف تحقق مستقبلية تحتاج أدلة ومراجعة مستقلة، وليست شارات تسويقية توضع على الواجهة.

- إعداد النشر يستخدم Gunicorn بدل الخادم المحلي القياسي، لكنه لا يمثل مراجعة أمان مكتملة. يلزم HTTPS، قيود المضيف، حدود الطلبات والمهل والمراقبة والإنذارات، حماية DDoS ومحاولات الدخول حسب IP أيضًا.
- MFA وSSO واسترداد آمن للحسابات، دعوات محدودة المدة، تغيير كلمة مرور إجباري عند أول دخول، وسياسة جلسات قابلة للإدارة.
- تشفير القرص والنسخ الاحتياطية وإدارة مفاتيح خارج المصدر، واختبار استعادة، وتحديد أهداف RPO/RTO.
- فحص برمجيات ضارة للملفات، حصص مساحة وعدد سجلات، حدود تحميل، تدقيق وصول وتنزيل المستندات، مخزن كائنات خاص عند التوسع.
- سجل تدقيق مقاوم للتلاعب وسياسة احتفاظ وتصدير أدلة؛ السجل الحالي قابل لتعديل مسؤول قاعدة البيانات ولا يخزن الفروق قبل/بعد.
- سياسة خصوصية ومعالجة وحذف واحتفاظ وموافقات وأدوار متحكم/معالج مناسبة للبلد والعقود الفعلية، وتقييم مكان إقامة البيانات.
- اختبار اختراق مستقل، مراجعة صلاحيات شاملة، فحص تبعيات صور التشغيل، مصفوفة متصفحات وقابلية وصول وتحمل الأحمال.
- فصل قواعد ومفاتيح بيئات التطوير والاختبار والإنتاج؛ منع بيانات الإنتاج في التجارب.

لا ترسل كلمات مرور أو OTP أو مفاتيح إلى المحادثة، ولا تخزنها في GitHub. وجود شيفرة حماية لا يغني عن تشغيلها وفحصها في بيئة الاستضافة الفعلية.

## تهيئة الاستضافة

الإصدار 0.1.1 يدعم تأسيس المالك عبر `/api/setup` فقط عند غياب أي مستخدم ومع وجود رمز خادم عشوائي بطول 32 حرفًا على الأقل. لا يوجد تسجيل عام. يمنع Origin مخالفًا ويقفل التهيئة بعد 10 محاولات فاشلة 15 دقيقة. التحقق من خلو المستخدمين والإنشاء داخل معاملة كتابة واحدة. لا يظهر الرمز في المصدر أو health أو عنوان URL، ويجب حذفه من إعدادات الاستضافة بعد التأسيس. الصفحة لا تستخدم كلمة مرور افتراضية.

## نسخة Netlify التجريبية 0.2.0

تستخدم نفس الأدوار الأساسية لكن مخزنًا مختلفًا: snapshots داخل Netlify Blobs مع قراءات strong وكتابة شرطية ETag للمعاملة الكاملة. واجهة العميل ترسل رقم نسخة كل سجل، والخادم يفحصه ثم يحفظ الحالة إن لم تتغير. فشل الحفظ لا ينشر رصيد إجازة أو موافقة جزئية. حالة الجلسات تقرأ من المخزن في كل طلب ولا تعتمد على ذاكرة وظيفة واحدة. كلمات المرور scrypt مع أملاح عشوائية، والجلسات تخزن ملخص الرمز فقط. مفاتيح المخزن والمستندات لا تختار من قيم المستخدم مباشرة.

حدود التجربة في README. ملخصات كلمات المرور والجلسات في snapshot الداخلي ليست ضمن تصدير المستخدم العادي. ملف النقل يشمل تعريفات الحسابات دون كلمات مرور، ويتطلب تعيين كلمات جديدة عند النقل. إعادة تعيين كلمة مرور مستخدم في نسخة Node يعيد تفعيل حسابه المستورد/المعطل؛ الإجراء للمالك فقط وينهي الجلسات السابقة.

التجربة لا تلغي حدود الخطة المجانية أو احتمالات بداية باردة أو حاجة مراقبة ونسخ احتياطي أو مراجعة أمان. لا تُستخدم لحفظ البيانات الوحيدة للمشروع؛ ولا يوجد اعتماد امتثال تجاري ضمن هذا التعديل.
